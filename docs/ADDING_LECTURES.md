# Add a lecture to Vitanova

Keep the HTML lecture file you upload. From the repository directory run:

```sh
python3 tools/add_lecture.py /path/to/MSS-Midterm-Anatomy-Lectures-13-14.html
```

The command reads the filename and lecture headings. When classification is clear, it copies the lecture to a consistent filename, registers it in `study-data.js`, adds shared navigation and study tools, extracts its questions, and refreshes the central bank. The hub derives navigation, counters, progress, and search from that registry. Existing lectures keep their filenames and permanent IDs.

The input file is never deleted. Keep temporary uploads outside the checkout and pass their full paths, so an extra unregistered HTML copy is not left in the published site. If an upload is already inside the checkout, its original remains available; review local links to that source filename before removing the duplicate yourself. The tool validates local asset paths but does not rename internal content links.

## When the filename is ambiguous

The tool stops before writing any file and explains which metadata it needs. Supply those fields explicitly:

```sh
python3 tools/add_lecture.py /path/to/new-lecture.html \
  --system MSS --exam Midterm --subject Anatomy --lectures 13-14 \
  --title "Nerves of the forearm" \
  --description "Forearm nerves, major branches, distributions, and common clinical injuries."
```

Use the actual content to choose metadata. Do not guess the exam period or subject. Only `Midterm` and `Final` are currently accepted exam periods. Future systems and subjects can use explicit `--system` and `--subject` values; their dashboards are derived automatically. Existing Past Papers categories remain supported; registering new past papers currently requires reviewed registry metadata rather than automatic CLI classification.

Use `--dry-run` first to see the category and planned file changes without writing them. All source parsing and question extraction happen before writes. Filename or ID collisions with different content are rejected. The copy step needs any lecture-specific local assets copied into the repository first. Absolute and parent-directory paths outside the repository are rejected. This tool does not execute uploaded JavaScript.

## What the lecture must contain

The original lecture HTML needs a title or `<h1>`, closing `</head>` and `</body>` tags, and a supported question-data array. The current formats are JavaScript data literals named `Q`, `Q1`, `Q2`, `QZ`, `L1`, `L2`, or `D`, either arrays of questions or objects containing arrays:

```js
const Q = [
  ["Question text", ["First answer", "Second answer"], 1,
   "The original explanation."]
];
```

The answer index starts at zero. Object-shaped individual question records, function calls, computed data, executable template strings, and unsupported MCQ layouts are rejected rather than partially imported. Identical duplicate questions within a lecture also require review. A new quiz implementation needs an extractor and browser adapter before it can inherit bookmarking and mistake review. Keep its original quiz implementation; do not rewrite educational content to force compatibility.

The current browser adapter supports the existing lecture layout: each question is a `.q` block with its question in a paragraph and answers in `button.o` elements. Those elements can be generated by the original inline quiz. The tool can validate extracted data, but **browser testing remains necessary for a new quiz implementation**.

## Review and verify

```sh
python3 tools/validate_site.py
python3 tools/refresh_question_bank.py --check
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.cjs
node tests/browser.cjs
```

The browser test needs the development-only Playwright installation described in the repository README. Review the added HTML and the registry entry. Check its classification, lecture numbers, title, and concise description against the actual lecture. Open the lecture and confirm:

- The original content, answers, explanations, scores, and Reset behavior are unchanged.
- Home, Back to subject, Previous, and Next work within the correct category.
- Each MCQ receives a bookmark control, including after Reset.
- An incorrect answer appears in mistake review; a correct revision can mark it mastered.
- Search and manually controlled subject completion include the new lecture.

The command is safe to run again: the same input does not add duplicate registrations or scripts. It refuses to overwrite an existing lecture with different educational content. For an existing registered lecture, passing its registered path refreshes shared references without changing its permanent ID.

## Stable IDs and existing bookmarks

`study-data.js` is the source of truth for lecture metadata. A lecture ID is permanent: changing its title or filename must not change its `id`. Use `--id` only to select that existing identity or assign a deliberate new identity. If renaming a file manually, update only its `file` field and keep the old URL as a redirect.

Question IDs fingerprint the permanent lecture ID, question text, answer options, and correct answer. They do not depend on display title, filename, group, array position, or other lectures. Reordering questions and regenerating the bank therefore keeps their IDs. Regeneration retains known older IDs in `legacyIds`, including IDs from the supplied Saved Questions upgrade, allowing saved bookmarks to resolve to current questions. Unmatched saved IDs are retained for recovery rather than discarded.

Changing the actual question or correct answer changes its fingerprint. Such content edits require explicit permission and a reviewed migration. Regenerate from the current bank rather than deleting it first, so historical aliases survive:

```sh
python3 tools/refresh_question_bank.py
```

Never edit `study-questions-data.js` by hand. The application stays static and works on GitHub Pages; Python is a maintenance tool, not a runtime dependency. Commit, push, and publish only after review.
